## Shooting at the screen's edge with touch / pen (worker "edgereload")

User (Surface Pro 7, 2736 x 1824, 200 % scaling): "Shooting on the border of the screen reloads."

Cause: the game counts a gun on the window's outermost pixel as off the screen (that is how a mouse, which is kept
inside the window, reloads: push it against the edge). SDL clamps a touch / pen to 0 .. width-1, so a tap at the edge
landed exactly there and reloaded; pixel 0's left side is also exactly the picture's edge (arcade x = -half width,
y = +-192), which the strict "inside" test counted as off. Not the cause: the 200 % scaling (SDL 3 on Windows is
per-monitor DPI aware: window coordinates are pixels, the input test shows 2736 x 1824 window = 2736 x 1824 pixels).
Also found: Windows turns touch / pen into mouse input too, which our raw-input watch could count as a "second mouse"
and switch to relative mode (each mouse its own crosshair, able to run past the window edge).

| What | Before | After |
|---|---|---|
| Touch / pen on the edge pixel (widescreen) | Reload | A shot (aimed at the pixel's middle) |
| Touch / pen on the top / bottom edge (4:3 too) | Reload | A shot |
| Touch / pen on a 4:3 black bar | Reload | Reload (off the arcade's 496 x 384 screen; a handy reload zone) |
| Touch reload | (only the edge pixel / Auto reload) | A second finger down while one is on the screen |
| Pen barrel button | Player 1 start (SDL: middle button) | Reload (the eraser end reloads too, as before) |
| Mouse pushed against the edge | Reload | Reload (unchanged); one pixel inside is a shot |
| Touch / pen as a "second mouse" | Could switch to relative mode | Ignored (only real mice count) |
