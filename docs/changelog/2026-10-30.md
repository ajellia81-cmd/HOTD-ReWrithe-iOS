## netfix: rejoin on two real PCs, LAN joins without a code, Wait / Continue when a player leaves

From the user's first two-PC test (brother's PC, same home network).

| What | Before | After |
|---|---|---|
| Joiner closes its window (or Esc > Exit) mid-game | it sent the end-of-game BYE: the host's game stopped ("The other player left the game"), so nobody could join again | it sends "leaving": the host keeps the seat open; joining again (code, or one click in the LAN list) puts it back in the same game |
| A player leaves / drops mid-game | two PCs: the host waited, no choice; up to four PCs: the game went straight on without them | the game waits for everyone ("P2 left: waiting for them to join again (same code). Enter / Start: go on without them" on the host; "P2 left: the host waits for them or goes on" on the others). Going on: two PCs = the host plays alone, still open for a join; four PCs = the seat is free, the rest play on (same hashes on every PC) |
| LAN list | click a game, then type its code | click a game: it joins (the host's LAN announcement carries the password; `--lan-code` keeps the old way). Internet joins still need the code |
| LAN announcement | 255.255.255.255 only (Windows sends it out of one adapter: a VPN / Hyper-V / VirtualBox adapter can take it) | also every adapter's own subnet broadcast |
| Code pasted right after opening Join (e.g. joining again after a restart) | used the code's internet address when the LAN list had not heard the host yet: routers seldom loop that back, "No answer" | waits up to 2.5 s for the LAN list, then uses the host's LAN address |
| "No answer" from a host the LAN list hears | the generic firewall / port hint | "The host's PC is on your network but its game does not answer": allow hotd.exe in Windows Firewall (Private) on the host's PC |

Causes found: the clean close's BYE (the main one: the existing rejoin test killed the joiner, which never sends
BYE, so it passed); the internet address in the code before the LAN list was heard; the LAN list's code step.
Not reproducible on one PC: the firewall itself and a second real adapter (binding a test host to the LAN address
would pop up the firewall question on this PC).

Tests (127.0.0.1, hidden windows / headless): `hotd_nettest` all passed (new: the LAN-open announcement round trip and
refusals, this PC's adapters' broadcasts, the "left" bits in PING, BYE "leaving"); `netplay_menu_test.ps1 -Mode
rejoin`: lan-open PASS, rejoin-close (the joiner's window closed at frame 1200, a new menu joiner with the code) PASS,
rejoin-kill (killed hard, the new joiner by one LAN click) PASS, all hash 29c07e646e8dae3b at 3000 frames;
`netplay_join_test.ps1` rejoin / leave: chapter 1 ended at 15631, hashes ca14e40c69459616 on both; continue (host
`--net-drop 3`): the host went on alone at frame 3002 to 20000; `netplay4_test.ps1` (4 PCs): leave + wait + rejoin
SYNC PASS 604ed7f9d8b2db42 (the same as killed + quick rejoin), leave + continue after 3 s SYNC PASS on 3 PCs.
