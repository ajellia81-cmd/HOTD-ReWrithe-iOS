# Changelog 2026-10-26

- Online join code (worker "onlineux"): before, joining over the internet meant a long share code
  (`HOTD-1G5804A1WRFY-K7QF2MXD`) or the host's address plus a password typed separately; after, the host gets one
  short code, `K7QX-M2PD-H4TA-9BCE` (16 letters / digits, no 0 O 1 I L, any case, dashes optional), holding the address,
  port and a 40-bit password; a typo is refused at once in plain words. On the same network the code finds the host by
  itself. A new code each time you host. Protocol 13 (every PC needs this build).
- Online pages: before, Host showed Password, New Password, Share Code ("Click to copy", stuck on "Copied"), LAN
  Address; Join had Address / Code, Password, Paste Share Code. After: Host a Game shows Your Code, Copy Code ("Copied!"
  for 2 s), who joined, Start; Join a Game has one Join Code box, Paste Code (Ctrl+V too), Join; every row has a short
  help line.
- Online pause: before, one PC's pause froze the other with "Waiting for the other player..." (and after 6 s the host
  treated a paused player 2 as gone); after, every other PC shows "P1 PAUSED" (the player who paused) and the link
  stays up.
- Cut-scene skip online: before, any player's trigger skipped a cut-scene for everyone; after, only the host's does
  (others see "Only the host can skip").
- Online sounds: before, the PC that runs ahead (usually the host) lost most of the other players' gunfire sounds (a
  shot re-run after a wrong guess played silent); after, those sounds are played as soon as the shot is known (a few
  frames late; ~170 per PC in a 2-player 40,000-frame test, ~2,800 per joiner with four PCs, all lost before).

## CPU teammates like real players; harder 3-4 player games (worker "cpuai")

User: "CPU teammates still robotic: aim-bot, no randomness, always aim at the same exact place; sometimes ignore the
boss's weak spots; still shoot researchers; CPU Normal too easy; 3P / 4P too easy." Details: docs/coop4.md section 21.

- **Aim like a hand:** before, a CPU's sight eased onto the centre of a creature and settled there (its error shrank
  to nothing), firing in a fixed rhythm. After: a reaction time that varies (sometimes a longer look), a quick flick
  that overshoots or falls short, then small corrections that never get it perfect; each burst picks a spot on the body
  (head, chest, arms, by size), so the shots spread; now and then a hasty shot just before the sight is on, a late
  reload, a longer pause. Some shots miss.
- **Bosses:** before, the Magician's weak parts and the Chariot's hand only. After, always the weak part: the Chariot's
  hand while armoured (no shots while the armour falls off), its chest without armour, the Hermit's weak part (part
  27, the only one that hurts him), the Magician's four parts, the Hanged Man's body (all his parts hurt the same).
- **Hostages / researchers:** the Hanged Man's two captives counted as part of the boss (now: people); the CPU never
  picks a spot near a hostage and holds fire while any hostage could be in the shot's reach.
- **4 players:** a researcher shot by someone took a life from whoever was next in turn (like an enemy hit); now the
  shooter loses it, as at the arcade.
- **3-4 players harder:** new Options > Gameplay "4P Enemy Toughness" (+50 % a player by default): with 3 / 4 players
  the creatures take 1.25x / 1.5x the shots; "4P Boss Hit Points" now +50 % a player (was +25 %; a launcher.ini still

## Draw Depth: the arcade's polygon sort (worker "clipfix")

The user saw the two-axe zombie's pants sticking out in the attract demo. The original does **not** do that: MAME
(attract snaps 120-240, same frames) shows his shirt over the waistband. Cause: the Model 2 has no depth buffer; it
sorts whole polygons (each by the min or max z of its corners, a polygon flag) and draws the nearer one over the
farther. Our renderer used a per-pixel depth buffer, so a waistband lying a little in front of the shirt hem showed.

| | Before (Depth Buffer) | After (Arcade Sort, the new default) |
|---|---|---|
| Attract, two-axe zombie | black waistband over the shirt hem | the shirt hem over it, as MAME |
| Chapter 3, after the first door (frame 2700) | a brown door over the grey wall | the grey wall in front, as MAME snap 354 |
| Chapter 1, the pond's tombstones | half sunk in the ground | standing out, as MAME snap 50 |
| Chapter 2, bedroom corner (frame 5840) | as MAME | as MAME (the next room's wall stays behind) |
| Ending, the car at the gate | in front of the pillar until an 8-unit tweak; a dark shadow on the ground | behind the pillar, no shadow, as MAME snap 776 |
| PC models | depth buffer | depth buffer (the 1998 PC game used a z-buffer): no change |

- Options > Video > **Draw Depth**: Arcade Sort / Depth Buffer (launcher.ini `drawdepth=sort|buffer`,
  `--draw-depth sort|buffer`). Draw only: the game logic is unchanged.
- How: each arcade polygon gets one depth, its sort key (min / max corner z by its flag, z-sort mode 0 = the previous
  polygon's, rounded to the hardware's 16-bit key); on a tie the earlier model wins, inside a model the later
  polygon. The tie rule is the one that matched MAME in all places compared; the hardware's z-sort register value is
  not known (taken as 1.0). The old depth tweaks (decal layers, floor pull, pushes) only apply to Depth Buffer.
- Speed: the same (Chapter 1 headless, 16,600 frames: Depth Buffer 0.671 / 0.682 ms a frame, Arcade Sort 0.675 /
  0.726 ms). The game already had a depth buffer; the sort adds a small key table per stage (64 bytes a triangle).
- Pictures: `build\clip_shots\` in the clipfix worktree (ours before | after | MAME).
