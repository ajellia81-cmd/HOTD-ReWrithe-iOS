## autostart: Play no longer starts a 4-player game by itself

User: "when I started Play it started a 4-player arcade Chapter 1 immediately". Their log: the boot's attract began,
then within a second "player 2 starts", "attract: start pressed, Chapter 1 with 1 player(s)", "player 4 joins",
"player 3 joins".

Cause: the computer teammates (launcher.ini `players=4` with `p2bot` / `p3bot` / `p4bot` set). A teammate seat that is
waiting "joins at once" by pressing its start button, and the teammates ran in the boot's attract too. In the attract a
start button (or a trigger) is a game's start, so player 2's CPU started Chapter 1 and the CPUs for 3 / 4 joined. Not a
pad, the mouse or the keyboard.

| What | Before | After |
|---|---|---|
| Play / the boot's attract with CPU teammates | Chapter 1 started by itself in about 1 s (the CPU's start) | the attract runs; nothing starts until a person presses start; the CPUs join after that, as in a game started from the menu |
| The attract after a game over (title flow) with CPU teammates | the CPUs' start began the next game | the attract runs on |
| A pad plugged in (or found at launch) with buttons / a trigger held | its first state counted as presses (in the attract: Enter = the main menu; in play: a start / shot) | held buttons are ignored until let go; the trigger pulled all the way likewise |

- Code: bot.cpp (`Bot::frame` / `Bot::seatInput`: no teammate input while `Runtime::attract`; their state looked at
  again when the game starts), pads.cpp / pads.h (`Pads::staleButton`: buttons held when the pad is opened, or reported
  down in its first 0.3 s, are ignored until released; `menuKey` ignores pads not opened yet).
- The launch click's / Enter's release reaching the game was checked: a release is not a press anywhere (no change).
- New input-test step (Remake walk, act 38): the boot with 4 players and every other seat a CPU, a virtual DualSense
