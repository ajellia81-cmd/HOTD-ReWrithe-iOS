## Linux, Steam Deck and cross-play

- **The game runs on Linux** (built and tested in WSL Ubuntu): the same results as Windows in every check (input test
  0 failed, Chapter 1 ends at 16695 with both models, Chapter 4's run reaches the ending at 34967).
- **Online co-op between Windows and Linux** (protocol 10): one encryption library on every system (Monocypher:
  CPace on X25519, XChaCha20-Poly1305, BLAKE2b) instead of Windows-only CNG. Same protections as before (password
  key exchange, replay window, 20-try lock, HELLO rate limit). A Linux host and a Windows joiner played 40,000 frames
  without a desync. Both PCs need this build (an older one is told "another version").
- **Linux package**: `tools/make_linux_package.sh` makes a folder like the Windows package (bin/hotd with its own
  SDL, hotd.sh, data/ folders) and a .tar.gz, with Steam Deck steps in its README.

## Jukebox: arcade lengths, loops and seeking (jukelen)

The arcade sound board reports nothing about its sounds, so the Jukebox had no length for any arcade entry. Now every
arcade code is measured once on the player's PC from their own ROMs (4 hidden background processes on the first
Jukebox visit, about 55 s; a cache in the settings folder, keyed by the ROMs' hash; nothing from the game in the
repository). Method and the measured table: docs/runtime.md "Arcade lengths".

| What | Before | After |
|---|---|---|
| Arcade entries' time | elapsed only ("0:12"), "Arcade board: no length" under it | time / total and the bar like the PC: Chapter 1 "0:15 / 2:32", ", loops 2:24" after the name |
| Looping arcade songs | Loop all moved on after the PC file's length (or 4 min) | after intro + one loop as measured (e.g. Chapter 1 8.59 + 143.71 s, Boss 0.55 + 49.71 s, Name entry 0.30 + 13.70 s); the bar stays in the loop once it went round |
| Jingles / effects / voices | "ended" after 1.5 s of silence, no length | their length (Game over 6.60 s, Title 59.39 s once, Ending 80.78 s once; effects 0.42-9.49 s); 14 held sounds marked "loops" |
| Seeking arcade sounds | not possible (PC music only) | click the bar: the code again, the board run muted to the place ("Seeking"), Chapter 1 to 60 % (91 s) in about 3 s |
| `--jukebox-test` | arcade: sounded / not | also lists every arcade length and checks them on the output: 233 checks 0 bad (ends within 0.3 s; each loop's envelope fits best within 0.00-0.02 s of the measured loop, correlation 0.965-0.996; the seek lands at 91.38 s of 91.38 s, its next 20 s match the same place played through, 0.972) |

What the arcade's region setting (0x51F791, JAPAN 0 / USA 1 / EXPORT 2) changes, read from the code:
- **Text / pictures only:** the voice-message subtitles (Japan: one picture per line, vertical on the right, sprite banks
  0x27 + the chapter's; USA: the English text line at the bottom), the chapter cards (table 0xCD4C0), the RELOAD hint
  under RELOAD (0xCA700, and its bank 0x38 / 0x4F), the attract tutorial's speech bubbles (0xAB290..), the opening
  mission briefing picture (0x81).

  opening title's time (Japan 180 frames, USA 60). So Game Text is a **text-only switch**: the logic keeps the USA
  region, only the drawing picks the Japanese pictures. One catch: the briefing picture shows for the USA's 60 frames
  (about 1 s) instead of Japan's 3 s, so the timing stays the same.
- The PC port's `language=JAPANESE` (0xDA0CEE: 4 -> 0) is the same switch: the PC's region index into the same tables
  (5 columns, the PC's own 4), and SPR.RBH has the Japanese pictures; our PC models show them through the sprite map.
